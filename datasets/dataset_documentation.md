# SAP SmartSupply AI — Synthetic Dataset Documentation

**Document Class:** Dataset Reference & Data Dictionary
**Scope:** Synthetic supply-chain data generated for the SAP SmartSupply AI project
**Related Files:** `products.csv`, `sales.csv`, `inventory.csv`, `suppliers.csv`, `purchase_orders.csv`, `warehouses.csv`, `defects.csv`

---

## 1. Purpose

This document describes the seven synthetic datasets generated for the SAP SmartSupply AI project. It defines each file's schema, field types, business meaning, and inter-table relationships, so the data can be consumed reliably by the ingestion pipeline, feature engineering layer, and downstream ML models (demand forecasting, supplier risk prediction, inventory optimization) and analytics modules (7 QC Tools).

## 2. Dataset Inventory

| # | File | Grain / One Row Per | Primary Key |
|---|------|----------------------|-------------|
| 1 | `products.csv` | One product / SKU | `product_id` |

## 3. Entity Relationships

```
suppliers.csv ──(supplier_id)──< products.csv ──(product_id)──< sales.csv
      │                                │
      │                                ├──< inventory.csv >──(warehouse_id)── warehouses.csv
      │                                │
      └──(supplier_id)──< purchase_orders.csv ──(product_id)──┘
                                       │
                                       └──< defects.csv
```

- Every `product_id` traces back to exactly one `products.csv` row.
- Every `supplier_id` traces back to exactly one `suppliers.csv` row.
- Every `warehouse_id` traces back to exactly one `warehouses.csv` row.

## 4. Dataset Schemas

### 4.1 `products.csv` — Product Master Data

Master registry of all SKUs. Feeds forecasting, supplier linkage, and reorder logic.

| Field | Type | Description |
|---|---|---|
| `product_id` | String (PK) | Unique product/SKU identifier. |
| `product_name` | String | Descriptive product name. |
| `category` | Categorical | Product family (e.g., Raw Materials, Electronics, Semiconductors). |
| `unit_price` | Decimal | Standard selling price per unit. |
| `lead_time_days` | Integer | Expected procurement-to-availability duration. |
| `supplier_id` | String (FK → `suppliers.csv`) | Primary supplier for this product. |
| `reorder_point` | Integer | Stock threshold that triggers a replenishment order. |
| `safety_stock` | Integer | Minimum buffer stock to absorb demand/lead-time variability. |

**Validation rules:**
- `unit_price` ≥ 0.
- `reorder_point` ≥ `safety_stock` (reorder point should sit at or above the safety buffer).
- `supplier_id` must exist in `suppliers.csv`.

---

### 4.2 `sales.csv` — Sales Transactions

Historical demand signal used for forecasting and KPI dashboards. Recommended volume: 10,000+ rows (50,000+ ideal).

| Field | Type | Description |
|---|---|---|
| `order_id` | String (PK) | Unique sales order/transaction identifier. |
| `order_date` | Date | Date the order was placed. |
| `product_id` | String (FK → `products.csv`) | Product sold. |
| `quantity` | Integer | Units sold in the transaction. |
| `revenue` | Decimal | Total revenue generated by the line item. |
| `customer_region` | Categorical | Geographic region of the customer (e.g., North, EMEA, APAC). |

**Validation rules:**
- `quantity` > 0.
- `revenue` ≥ 0, and should be consistent with `quantity × products.unit_price` within a reasonable tolerance.
- `order_date` must be a valid, non-future date.

---

### 4.3 `inventory.csv` — Inventory Snapshot

Live stock position per product per warehouse. Drives stockout alerts and reorder automation.

| Field | Type | Description |
|---|---|---|
| `inventory_id` | String (PK) | Unique inventory record identifier. |
| `product_id` | String (FK → `products.csv`) | Product being tracked. |
| `warehouse_id` | String (FK → `warehouses.csv`) | Warehouse/facility holding the stock. |
| `stock_on_hand` | Integer | Physical units currently in the storage location. |
| `stock_reserved` | Integer | Units already allocated to open sales/production orders. |
| `last_updated` | Datetime | Timestamp of the most recent stock count/sync. |

**Validation rules:**
- `stock_on_hand` ≥ 0; null values default to `0` and raise a critical data-quality alert (never silently imputed as valid stock).
- `stock_reserved` ≤ `stock_on_hand`.
- Flag as **overstock** if `stock_on_hand` > 10 × `products.safety_stock` for that product.
- Flag as **stockout risk** if `(stock_on_hand − stock_reserved) < products.reorder_point`.

---

### 4.4 `suppliers.csv` — Supplier Master & Performance

Quantitative and descriptive supplier attributes feeding risk scoring.

| Field | Type | Description |
|---|---|---|
| `supplier_id` | String (PK) | Unique supplier identifier. |
| `supplier_name` | String | Registered business name. |
| `country` | Categorical | Supplier's country of operation. |
| `category` | Categorical | Supply classification (e.g., Raw Materials, Logistics, Electronics). |
| `lead_time_days` | Integer | Average duration from PO release to warehouse dock. |
| `on_time_delivery_rate` | Decimal (%) | Historical percentage of deliveries meeting the SLA date. |
| `defect_rate_ppm` | Decimal | Parts-per-million defect rate across supplied materials. |
| `financial_stability_score` | Decimal | Normalized credit/liquidity score. |
| `geopolitical_risk_index` | Decimal | Composite score for regional/transit risk exposure. |

**Validation rules:**
- `on_time_delivery_rate` between 0–100.
- `defect_rate_ppm` ≥ 0.
- `financial_stability_score` and `geopolitical_risk_index` normalized to a documented scale (e.g., 0–1 or 0–100) — keep consistent across the dataset.

---

### 4.5 `purchase_orders.csv` — Procurement Records

Tracks replenishment orders placed against suppliers; used for lead-time and procurement analytics.

| Field | Type | Description |
|---|---|---|
| `po_id` | String (PK) | Unique purchase order identifier. |
| `supplier_id` | String (FK → `suppliers.csv`) | Supplier the order was placed with. |
| `product_id` | String (FK → `products.csv`) | Product being procured. |
| `quantity` | Integer | Units ordered. |
| `order_date` | Date | Date the PO was issued. |
| `delivery_date` | Date | Actual (or expected) date of receipt. |

**Validation rules:**
- `delivery_date` ≥ `order_date`.
- `quantity` > 0.
- `delivery_date − order_date` should be reasonably close to the supplier's `lead_time_days` (large deviations indicate a delay worth flagging).

---

### 4.6 `warehouses.csv` — Warehouse Master Registry

Physical infrastructure nodes and capacity thresholds, used for capacity-utilization and logistics analytics.

| Field | Type | Description |
|---|---|---|
| `warehouse_id` | String (PK) | Unique warehouse identifier. |
| `city` | String | Municipality where the warehouse is located. |
| `region` | Categorical | Logistics cluster (e.g., North, EMEA, APAC). |
| `total_capacity_units` | Integer | Maximum storage capacity (pallet/bin slots). |
| `utilized_capacity` | Integer | Currently occupied storage slots. |
| `daily_operational_cost` | Decimal | Aggregated daily overhead run-rate (USD). |
| `automation_level` | Categorical | Facility maturity: `Manual`, `Semi-Automated`, `Fully-Automated`. |

**Validation rules:**
- `utilized_capacity` ≤ `total_capacity_units`.
- Flag **capacity bottleneck** when `utilized_capacity / total_capacity_units` > 0.90.

---

### 4.7 `defects.csv` — Quality Defect Records

Feeds the 7 QC Tools module (Pareto charts, histograms, control charts, fishbone analysis) and root-cause automation.

| Field | Type | Description |
|---|---|---|
| `defect_id` | String (PK) | Unique defect record identifier. |
| `product_id` | String (FK → `products.csv`) | Product associated with the defect. |
| `defect_type` | Categorical | Classified failure category (e.g., Structural, Cosmetic, Dimensional). |
| `defect_count` | Integer | Number of defective units recorded in this observation. |
| `inspection_date` | Date | Date the defect was logged/inspected. |
| `severity` | Ordinal | Impact classification: `Low`, `Medium`, `High`, `Critical`. |
| `plant_location` | Categorical | Facility where the defect was recorded. |

**Validation rules:**
- `defect_count` > 0.
- `severity` restricted to the four defined levels (no free-text substitutes).
- `inspection_date` must not precede the corresponding product's introduction date, if tracked.

## 5. Data Cleansing & Preprocessing Rules

- **Null handling:** Critical numeric fields (`stock_on_hand`, `defect_count`, `quantity`) never silently default — nulls are flagged for review rather than imputed as zero without an alert.
- **Referential integrity:** All foreign keys (`product_id`, `supplier_id`, `warehouse_id`) must resolve to an existing row in their master table before ingestion.
- **Text normalization:** Free-text fields (`product_name`, `supplier_name`, `city`) are trimmed of whitespace/escape characters prior to any embedding or search indexing.
- **Outlier flags:** Overstock (`inventory.csv`) and capacity-bottleneck (`warehouses.csv`) conditions are computed at ingestion time, not left for downstream discovery.
